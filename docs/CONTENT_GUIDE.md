# Content Guide

## Knowledge collection

Create knowledge Markdown under `src/content/knowledge/`. Records have typed fields and a visibility status. New records default to `draft`. Published entries appear in indexes; unlisted entries receive direct static routes but are omitted from section indexes and sitemap. Draft and private-status content gets no public site route. The CMS blocks private saves because repository source is public.

The seeded AUST academic entry is a draft and includes only the degree, university, and thesis topic supplied by the owner. Add achievements, courses, supervisor names, research findings, dates, and publication status only when verified. Keep quote excerpts short and verify source and attribution.

Write project descriptions as a record of what exists today. Identify the project as personal, client work, or employment work, include its current status, and separate implemented features from planned scope. Avoid production, scale, performance and impact claims unless a repository, deployment or measurement supports them.

Technical articles should state the problem, constraints, design choices, alternatives, failure cases and lessons learned. Architecture notes should capture context, decision, consequences and status. Problem-solving entries should include the problem source, algorithm, complexity, edge cases and verification. Use descriptive tags and concise summaries. Verify dates, employer names and achievements against source documents before publishing.
